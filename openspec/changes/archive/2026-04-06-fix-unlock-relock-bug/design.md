## Context

目前，解锁机制依赖于 `useSecurity` 钩子中的长按逻辑。在移动端或 PWA 模式下，当用户松手触发解锁时，浏览器可能会随后发送一个冒泡的 `click` 事件。如果该事件被错误地捕获并触发了切换锁定状态的操作，应用会瞬间重新进入锁定状态。这在之前已经进行过多次修复，但由于缺乏状态转换保护（冷却时间），这一问题依然存在。

## Goals / Non-Goals

**Goals:**
- 消除解锁后的“秒锁”现象。
- 在 `useSecurity` 中引入状态转换的“冷却时间”（Cooldown），防止短时间内连续触发状态翻转。
- 优化 `DraggableDrawer.tsx` 中的事件处理，确保点击事件不与长按逻辑冲突。

**Non-Goals:**
- 更改基本的锁定算法或加密逻辑（如果存在）。
- 更改 UI 的视觉呈现方式（除非是为了支持状态反馈）。

## Decisions

- **引入 `lastToggleTime` 状态**:
  - **描述**: 在 `useSecurity` 中记录最后一次成功切换锁定状态的时间戳。
  - **原因**: 简单有效。通过比较 `Date.now() - lastToggleTime` 是否小于某个阈值（例如 500ms），可以过滤掉物理按键松开后的伪事件或误操作。
  - **替代方案**: 使用 `preventDefault` 拦截所有 `touchend` 后的 `click`。风险在于这可能干扰其他正常的 UI 交互，且在 React 跨平台合成事件中表现不一。

- **原子化状态更新**:
  - **描述**: 确保 `setIsLocked` 调用后，任何与其在同一个宏任务/微任务队列中的重复调用被抑制。
  - **原因**: 保证逻辑的一致性。

## Risks / Trade-offs

- [Risk] 用户可能真的想快速锁定 鈫 [Mitigation] 将冷却时间设为较短的 500ms，这对人类正常操作几乎无感，但足以过滤浏览器合成事件。
- [Risk] 不同浏览器的点击延迟（300ms 延迟） 鈫 [Mitigation] 使用 500ms 的保护期覆盖绝大多数浏览器的合成点击窗口。
