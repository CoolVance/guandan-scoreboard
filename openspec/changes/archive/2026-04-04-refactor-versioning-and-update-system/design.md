## 背景

当前应用缺乏主动的更新检测机制，用户难以感知 PWA 应用的新版本。原有的“云端/本地”模式逻辑模糊，且无法提供实质性的版本控制。我们需要一套基于静态 JSON 文件的检测方案，并通过 UI 状态灯实时反馈连接与更新情况。

## 目标 / 非目标

**目标：**
- 实现基于 `version.json` 的版本对比逻辑。
- 在侧边栏刷新按钮上实现多状态指示灯。
- 支持“下次提醒”与“跳过此版本”的逻辑。
- 教程界面动态显示应用版本。

**非目标：**
- 实现自动下载更新包（由 PWA 机制本身处理）。
- 修改计分引擎的核心逻辑。

## 技术决策

### 1. 版本定义与获取
- **决策**: 在代码中定义常量 `APP_VERSION`（例如 `2.1.0`）。在服务器 `public/` 下维护 `version.json`。
- **获取策略**: 使用 `fetch('/version.json?t=' + Date.now())` 发起请求。
- **理由**: 增加时间戳参数可以绕过浏览器或 PWA 的缓存，确保拿到的是服务器上最新的版本声明。

### 2. 更新状态管理
- **决策**: 使用 `localStorage` 存储两个 Key：
    - `skipped_version`: 用户选择“跳过”的版本号。
    - `last_version_check_result`: 缓存最近一次检测的结果（优化离线显示）。
- **对比逻辑**:
    1. 若 `remoteVersion !== localVersion` 且 `remoteVersion !== skippedVersion`，则标记为“有更新”。
    2. 若获取失败且当前在线，标记为“检测失败”。
    3. 若离线，标记为“离线”。

### 3. UI 表现：指示灯与弹窗
- **指示灯**: 在 `DraggableDrawer.tsx` 的刷新按钮上增加一个 `absolute` 定位的 `span` 元素。
    - **闪烁绿点**: 使用 Tailwind 的 `animate-ping` 或自定义动画实现脉冲效果。
- **弹窗**: 在 `App.tsx` 中增加一个 `UpdateModal`。
    - **立即更新**: 执行 `window.location.reload(true)`。
    - **下次提醒**: 仅关闭弹窗。
    - **跳过**: 更新 `skipped_version` 并关闭。

### 4. 教程内容与版本同步
- **版本号**: 修改 `TutorialOverlay` 组件接口，增加 `version` prop。
- **说明内容**: 更新教程中对应的“应用状态/刷新”步骤文案。
    - **文案策略**: 解释按钮右上角点的含义：🟢 有更新，⚪ 检测失败，⚫ 离线。
- **理由**: 确保用户在初次使用或查看教程时能理解新引入的视觉反馈机制。

## 风险 / 权衡

- **[风险]** PWA 的 `StaleWhileRevalidate` 策略可能导致 `version.json` 本身被缓存 ➔ **缓解**: 强制在 Fetch 请求中使用 `cache: 'no-store'` 和时间戳。
- **[风险]** 频繁的 API 检测 ➔ **缓解**: 仅在应用初始化加载时执行一次检测。
